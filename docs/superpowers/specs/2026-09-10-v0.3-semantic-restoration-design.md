# GPT Cleaner V0.3 Semantic Restoration Design

## Goal

Make semantic restoration the default GPT Cleaner route while preserving the deterministic safe cleaner and the existing CCSR integration as fallbacks. The first V0.3 release targets exact 1x output on an RTX 5060 with 8 GB VRAM.

## Scope

V0.3 includes:

- deterministic controlled degradation before generative restoration;
- ComfyUI Core SUPIR as the primary engine;
- multi-scale Laplacian fusion after generation;
- automatic, visible fallback from SUPIR to CCSR and then safe cleanup;
- an incremental Windows upgrade that preserves the installed runtime and downloads only missing V0.3 models;
- separate doctor and smoke-test evidence for safe, SUPIR, and CCSR paths;
- optional intermediate-image exports for diagnosing restoration failures;
- the Windows fixes found during the first real installation.

V0.3 does not include:

- semantic 2x or 4x output;
- SeeSR or official CCSR-v2 integration;
- automatic image captioning through an additional vision-language model;
- remote inference or commercial AI APIs.

## Product Modes

The web UI exposes two user-facing modes:

1. **Semantic restoration** — default. It requests SUPIR and permits controlled fallback.
2. **Safe cleanup** — deterministic local image processing with no generative model.

The old CCSR route remains installed and callable as an internal fallback and as an explicit smoke-test target. It is not presented as the recommended user-facing route.

Semantic output is restricted to exact 1x in this release. When semantic mode is selected, the UI selects 1x and disables 2x and 4x. Safe mode retains 1x, 2x, and 4x.

## Processing Architecture

```text
uploaded image
      |
      +--> safe mode --> deterministic preclean --> requested safe scale
      |
      +--> semantic mode
              |
              +--> controlled degradation at 768-1024 long edge
              |
              +--> SUPIR through ComfyUI Core
              |       |
              |       +-- unavailable or failed --> old CCSR
              |                                      |
              |                                      +-- unavailable or failed --> safe cleanup
              |
              +--> multi-scale Laplacian fusion
              |
              +--> exact original dimensions
```

Every response identifies the engine that actually produced the result. A fallback must never be silent.

## Controlled Degradation

Controlled degradation removes unstable GPT micro-texture before the model sees the image. It must be deterministic so repeated tests are comparable.

Each preset defines a working long edge:

- light: 1024 px;
- standard: 896 px;
- heavy: 768 px.

The original aspect ratio is retained. Width and height are rounded to model-safe multiples of 64 without exceeding the chosen working envelope. Images already smaller than the envelope are not enlarged during degradation.

The degraded image is produced by:

1. Lanczos downsampling when reduction is required;
2. a small Gaussian blur whose sigma is preset-controlled;
3. the existing luminance preclean at a semantic-specific strength that does not use the old strong edge-preservation rule.

No JPEG round-trip is used because it would introduce block artifacts that the restoration model could amplify.

## SUPIR Workflow

V0.3 uses ComfyUI Core nodes, not the third-party `ComfyUI-SUPIR` package. The API graph contains:

- `LoadImage`;
- `CheckpointLoaderSimple`;
- `ModelPatchLoader`;
- `SUPIRApply`;
- two `CLIPTextEncodeSDXL` nodes;
- `EmptyLatentImage` at the degraded image dimensions;
- `KSamplerSelect`;
- `BasicScheduler`;
- `SamplerCustom`;
- `VAEDecodeTiled`;
- `SaveImage`.

The baseline models follow the current ComfyUI SUPIR workflow template:

- checkpoint: `juggernautXL_v9Rdphoto2Lightning.safetensors`;
- model patch: `SUPIR-v0Q_fp16.safetensors`.

The installer does not download the optional Qwen caption model. V0.3 instead supplies a fixed restoration prompt focused on clean BJD/character materials and a fixed negative prompt rejecting dirty micro-texture, repeated strands, halos, deformation, text corruption, and tile seams. This avoids another large model and a simultaneous captioning workload on an 8 GB card.

Initial standard settings use the official template as the conservative baseline:

- sampler: `dpmpp_2m_sde`;
- scheduler: `sgm_uniform`;
- steps: 10;
- CFG: 1.5;
- SUPIR strength: 1.0 to 0.9;
- restore CFG: 4.0;
- denoise: 1.0;
- deterministic seed: 123.

Light and heavy presets vary degradation and Laplacian contribution first. They do not expand the sampling range beyond values shown to run in the official template until real-image A/B evidence justifies it.

## Multi-scale Laplacian Fusion

The generated image is resized to the degraded working dimensions before fusion. Original, precleaned, and generated images are converted to float RGB and decomposed into a five-level Gaussian/Laplacian pyramid.

The bands are blended by purpose:

- very-low frequency and silhouette: almost entirely original;
- coarse lighting: mostly original with limited generated contribution;
- 4-32 px material and shading: meaningful generated contribution;
- 1-4 px detail: mostly generated contribution;
- unstable micro-texture: never restored wholesale from the original.

Each preset stores generated contribution weights from finest band to the low-frequency residual. Standard starts at:

```text
[0.78, 0.72, 0.58, 0.46, 0.22, 0.03]
```

`structure_protection` modifies bands independently. Higher protection sharply reduces generated contribution in coarse and low-frequency bands, moderately reduces it in mid-frequency bands, and only slightly reduces it in fine bands. This protects shape without preserving every unwanted thin edge.

The reconstructed image is clipped to valid RGB, converted to 8-bit, and resized once to the exact original dimensions.

## Engine Detection and Fallback

The application reports separate readiness for:

- safe cleanup;
- ComfyUI transport;
- SUPIR Core nodes and both SUPIR models;
- legacy CCSR node and model.

Semantic requests follow this policy:

1. If SUPIR is ready, run SUPIR.
2. If SUPIR readiness fails or its job fails, record the reason and try CCSR.
3. If CCSR also fails, return safe cleanup.

A successful SUPIR or CCSR result continues through the same multi-scale Laplacian fusion. Safe fallback returns the deterministic precleaned image without pretending that semantic fusion occurred.

The response includes:

- `X-GPT-Cleaner-Mode`;
- `X-GPT-Cleaner-Engine` with `supir`, `ccsr`, or `safe`;
- `X-GPT-Cleaner-Fallback` with a compact reason when fallback occurred.

The UI reads these headers and states the actual engine in the result message. It must not describe a safe or CCSR result as SUPIR output.

## Configuration Compatibility

`config/default.json` defines the complete V0.3 schema. `config/local.json` remains an override, not a replacement. Loading recursively merges local values onto defaults so an older preserved local file automatically receives new V0.3 fields.

Configuration groups are separated by responsibility:

- `semantic`: working size, blur, prompts, SUPIR model names, sampling settings, VAE tile settings, debug export;
- `ccsr`: legacy model and tile settings;
- `presets`: safe cleanup values plus semantic degradation and fusion weights.

Invalid or incomplete arrays fall back to the standard defaults instead of reaching OpenCV with inconsistent pyramid weights.

## Intermediate Diagnostics

When `semantic.debug_intermediates` is true, a request saves:

- controlled degraded input;
- raw generated output;
- final Laplacian-fused result;
- a JSON manifest naming the selected engine, fallback reason, source dimensions, working dimensions, preset, structure protection, and elapsed time.

Files live under `runtime/debug/<job-id>/`. Debug export is off by default. Normal temporary uploads are still removed after each request.

## Windows Installation and Incremental Upgrade

`install.ps1` keeps the existing first-run behavior and adds the missing SUPIR models. It retains the old CCSR node and checkpoint.

`update.ps1` performs an in-place V0.3 upgrade:

1. download the latest GPT Cleaner source;
2. preserve `runtime/`, logs, models, and `config/local.json`;
3. update application code and scripts;
4. refresh lightweight app dependencies;
5. confirm ComfyUI contains the required Core SUPIR nodes, updating ComfyUI code in place when required while preserving `models/`, `custom_nodes/`, `input/`, `output/`, and user data;
6. keep and reapply the legacy CCSR import-path patch;
7. download only missing SUPIR checkpoint and model patch, using Hugging Face direct download followed by `https://hf-mirror.com` fallback;
8. run `doctor.ps1` unless explicitly suppressed;
9. start the updated application unless `-NoStart` is supplied.

The upgrade must not reinstall Python, PyTorch, the existing ComfyUI environment, or the old CCSR model.

The following real Windows fixes remain regression requirements:

- fully collect `nvidia-smi` output before reading `$LASTEXITCODE`;
- reject the Windows Store Python launcher stub and unchecked empty output;
- keep `huggingface_hub>=1.5,<2` compatible with the installed ComfyUI stack;
- use codeload zip after unstable Git clone failures;
- use the Hugging Face mirror after direct model-download failures;
- retain `GPT_CLEANER_SYSPATH_COMPAT` for the old CCSR package.

## Doctor and Smoke Tests

`doctor.ps1` prints independent PASS, WARN, or FAIL states:

- base runtime and CUDA failures are critical;
- safe cleanup readiness is critical;
- missing SUPIR nodes or models makes semantic status partial, not total failure, because fallbacks remain usable;
- missing CCSR is a warning when SUPIR is ready and a semantic-readiness failure when SUPIR is also unavailable.

Smoke-test commands are:

```powershell
.\runtime\venv\Scripts\python.exe .\scripts\smoke_test.py --safe
.\runtime\venv\Scripts\python.exe .\scripts\smoke_test.py --semantic
.\runtime\venv\Scripts\python.exe .\scripts\smoke_test.py --ccsr
```

With no flag, the smoke test runs safe and semantic because they are the product-default acceptance paths. `--semantic` verifies exact 1x dimensions and requires the response to disclose the actual engine. It passes with `supir`; a fallback is reported as PARTIAL rather than falsely reported as full semantic success. `--ccsr` explicitly exercises the legacy graph.

Unit tests cover:

- recursive default/local configuration merging;
- controlled degradation dimensions and deterministic output;
- Laplacian reconstruction and band weighting;
- engine-readiness classification;
- SUPIR graph node wiring and 1x dimensions;
- fallback order and response headers;
- preservation of the known Windows installation fixes in scripts.

## Acceptance Criteria

Code-level acceptance requires:

- all unit tests pass;
- safe smoke test passes;
- doctor distinguishes full, partial, and failed semantic readiness;
- semantic requests always return exact original dimensions;
- an actual fallback is visible in response headers and the web result message;
- the update script preserves existing runtime and local configuration;
- no external inference service or API key is introduced.

Real-image quality remains a separate Windows GPU acceptance gate. On the modern-witch/BJD source, SUPIR must visibly reduce fake strands, plastic highlights, dirty micro-texture, and repeated AI patterns; improve medium-scale material shading; avoid tile seams; and keep silhouettes, joints, and facial placement stable. Until that A/B run is reviewed, the release status is implementation-complete but visual-quality validation is partial.
